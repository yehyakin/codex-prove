# Sol 6 / Terra 常规 worker 对照

日期：2026-09-25。范围：v1.1 开发候选，非发布验证。

## 实验设计

- 比较 `gpt-6-sol` / `high` 与 `gpt-5.6-terra` / `high`；两者收到完全相同的
  regular-worker 指令，不用不同角色提示暗中改变难度。
- 三类合成 Python 维护任务：配置迁移与未知用户字段保留、依赖前沿与写入冲突、
  复用既有 helper 的 CSV 导出。每类每模型三次，串行、交错顺序，共 18 个 cell。
- 每次新建工作区；固定初始文件、提示、grader 和运行器身份。不是实际业务项目
  基准，也没有携带旧回答或完整会话历史。
- CLI 使用明确模型/effort、`workspace-write`、现有认证、临时会话；不加载用户
  config，不绕过 execpolicy，不改全局配置。没有角色热更新或 Native Nested 声明。
- 每个 cell 180 秒上限。超时、错误和缺失指标保留，不自动重试或替换模型。
- 先验证已知错误基线会失败、参考实现会通过，再测试真实 macOS 验收沙箱。
- 模型退出后，独立执行公共/新增测试及不提供给 worker 的外部验收；沙箱禁止
  写入、网络及 `/Users` 读取，Python 不加载用户启动代码，环境不继承凭据。
- 验收需实际测试数、无 skip、成功凭据及退出状态；提前退出 0 不算通过。
  文件、缓存、符号链接及候选快照纳入范围检查；实际测试 diff 与执行轨迹另行人工复核。

这不是通用不可信代码执行服务。外部 grader 没有发给 worker，但同机目录不构成
不可绕过的隐藏题库隔离；任务明确限制读写范围。模型选择证据来自 Host 的 CLI
调用与完成记录，不来自子代理对不可见字段的自述。

## 预试验问题与排除规则

正式统计前中止了两批预试验，原始目录保留，不覆盖或混入正式统计：

1. 一批已完成一个 Sol cell、另一个 Terra cell 被中断。grader 曾对保证为 dict
   的输入追加未声明的非 dict 异常要求。这个 false failure 是测量错误，不是模型失误。
2. 第二批完成一对配置迁移 cell，下一 cell 被中断。独立审计发现：默认值验收不精确、
   helper 调用次数误限、提前退出可能假通过、外部评分未延续权限限制、公开测试未重跑、
   提示未冻结、缓存不在快照内。修补并通过针对性反例后才冻结正式实验。

排除原因是实验协议缺陷，而不是成绩不好；这几次调用仍消耗了实际账号资源。
没有账单数据，因此既不把它们当成免费，也不声称下面的正式 cell 统计是本次开发总成本。

## 结果与角色决定

18 个正式 cell 已完成，无超时、自动重试或模型降级。下表的“通过”**仅指冻结
检查集**，不是完整任务正确率：随后发现了检查集未覆盖的真实错误，见下一节。

| 模型（均 high） | 冻结检查通过 | CLI 耗时中位数 | 9 次总耗时 | 输入 token（其中缓存） | 输出 token |
| --- | --- | --- | --- | --- | --- |
| GPT-6 Sol | 9/9 | 85.520 秒 | 811.017 秒 | 1,333,644（1,111,168） | 31,589 |
| GPT-5.6 Terra | 9/9 | 88.783 秒 | 852.541 秒 | 1,564,637（1,408,256） | 34,467 |

分任务耗时中位数：配置迁移 Sol 90.133 / Terra 94.067 秒；调度函数 Sol 93.753 /
Terra 98.007 秒；CSV Sol 79.756 / Terra 68.680 秒。单次快慢会反转，不能据此说
新模型对所有任务更快。Sol 总输入较少，但其中未缓存输入反而更多；不能将总 token
降幅直接当成费用降幅。

[冻结数据、原始夹具/提示、18 份候选源码及后验诊断](worker-pilot-2026-09-25.json)
保留每次结果、输入与候选哈希；可重建候选，不必再次调用模型。当前 runner/fixture
已补强边界；JSON 内的 `frozen_fixtures`
保留实际试验版本，包括当时尚未发现问题的参考实现，不应当作生产实现复用。

### 后验边界诊断：共享引用

检查实际代码与新增测试时，发现 Sol 第三次配置任务额外测试了 Python 字典共享引用。
将同一个字典同时用于 `workers`、`execution` 和未知的 `backup` 字段时，直接在
deepcopy 后的 workers 上删 legacy key，仍可能误改输出中的 backup，因为 deepcopy
保留对象图内的别名。它违反了“保留未知字段原值”的要求。

- 冻结 grader 没有这一项，其参考实现同样漏掉；这是验收覆盖缺口，不是模型证明正确。
- 对原来的 6 份配置候选统一补跑相同检查，不改候选、不重新提示模型：**Sol 1/3
  通过，Terra 0/3 通过**。另外 5 份候选存在该问题，不能按完整要求接受。
- 这是由已见样本引出的**后验探索性检查**，不能回填成预注册胜率，更不能据此
  宣称 Sol 全面胜出。两套结果分别保留，不挑最好的一次。
- 已修复未来使用的参考实现、补上外部边界检查和反例回归；没有重跑付费模型来
  把这批有缺陷的结果“刷成通过”。

这说明 controller 必须检查实际逻辑与要求，而不只接收 worker 或测试的一句 PASS。
无需因此给每个普通任务再加一个固定 reviewer。

### 执行轨迹观察

18 份实现、测试改动及命令轨迹均已检查；保护文件保持不变，helper 被实际复用，
公共/新增测试在最终候选上由 Host 重跑。另保留这些瑕疵：

- Terra 的配置任务 r2/r3 尝试了任务包禁止的只读 Git 命令，在非 Git 夹具里无效；
  没有仓库写入，但不能把功能通过说成任务包执行完全合规。
- Sol 的调度 r2 有一次 BSD `nl` 参数错误，随后自行修正；CSV r2 在回合内遇到
  一次自检失败并修正，最终检查通过。没有要求新授权。
- 部分调用读取了本机 verification Skill。`--ignore-user-config` 不等于隔离全局
  Skill 发现；测试测到的是本机 CLI 行为，不是去除全部上下文后的纯模型速度。

**本轮决定：保持 Astra 主控、Sol 6 专项攻坚、Terra 常规、Luna 6 明确批处理的
现有候选映射。** Sol 6 值得继续在常规任务试用，但这些小样本没有提供足够稳健的
质量/成本依据来全面撤掉 Terra。没有新成本百分比，没有向全局安装或发布。

## 可复现入口与限制

- [runner](../../tests/worker_model_pilot.py)、[夹具与外部检查](../../tests/fixtures/worker_model_cases.py)、
  [离线反例测试](../../tests/test_worker_model_pilot.py)。默认只做不调用模型的离线校准；`--run-models`
  才会发起 18 次账号用量调用，详情见 [Forward validation](../../tests/forward-tests.md)。
- 完整 PROVE A/B 基准仍使用 [原协议](../../tests/v100-ab-benchmark.md)；其至少六场景、
  三次重复的门槛没有降低。这轮不测试 controller、并行调度、Windows 或完整项目交付。
- 这些小夹具在日常使用中可能适合 Direct；实验为比较执行层而固定委派，不能用来
  推导“小任务也应委派”，或当作复杂真实项目基准。
- token 按 CLI 原始 usage 记录；cached input 是 input 的子集。墙钟包含 CLI 启动、
  模型、工具与测试，不等于纯推理耗时。共享后端负载和缓存仍会带来波动。
- 实扣 Codex credits 和账单费用不可用。无总工作流节省百分比，无新增 README 成本承诺。
- 全局安装、全新 Desktop custom-role 发现、GitHub CI、提交/Push 与发布均不属于本轮结果。

### 2026-09-26 运行器边界修正

发布前离线审查补上两个反例：快照现在也记录空目录，避免未授权目录创建漏检；
候选导入或测试持续替换 `unittest` 测试框架时拒绝评分，不能靠替换运行方法伪造成功。
这些修正没有改写以上 18 次历史调用或重新调用模型。

验收器与候选仍处于同一 Python 进程；该完整性检查不是防恶意代码篡改的安全隔离。
成功 receipt 只支持冻结检查结果，最终接受仍须检查候选源码、实际测试 Diff 与任务覆盖。
