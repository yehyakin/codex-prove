## 改动及风险边界

| v1.0 行为 | v1.1 候选行为 |
| --- | --- |
| 显式调用总先建 controller | 先路由；简单任务仍 Direct |
| 每个 Agent 先空跑一回合自证 | Host 有权威选择记录即可发送首轮完整任务 |
| 没有 child 元数据会卡在自证 | 不用 child 自述证明它无法观察的字段 |
| 模板缺字段即 BLOCKED | 必要语义必须明确；可从既有证据修复的格式缺项不阻塞 |
| owner 写过文件后永不能换人 | 停稳旧 worker 及写进程、保留 Diff 和历史后可交接 |
| 只有一次修正机会 | 有进展的窄修复可继续；连续无进展、预算或真实边界限制恢复 |
| 缺结构化摘要继续阻塞 | 可只取结果、检查实际文件或补跑验证；无证据仍不能 PASS |
| 前后快照被称为“零写入证明” | 只证明净变化，不证明临时写入或进程已经停止 |
| 重复全套审核和上下文 | 复用未失效的证据；参考与挑战按需加载 |

不会改变：用户授权优先、一个活跃写入者、worker 不再委派、真实 Diff 审核、
可证伪验收、不得伪装模型切换、高风险边界、安装事务和旧版本恢复。

### 回滚修复与当前验证

修复范围是已存在的迁移恢复缺陷：当撤离当前文件或恢复旧文件失败，保留事务副本、
输出精确 recovery path、继续尝试恢复其他已管理文件并返回失败。
无法移开的目标不得被旧副本覆盖。成功回滚仍清理事务临时目录。

POSIX 新增 **8 项**真实故障注入，分两组先失败再通过：

- 安装/卸载各覆盖恢复移动失败和当前目标撤离失败，保留副本而非覆盖。
- 安装/卸载各覆盖“移动成功后、标记前收到 SIGTERM”：回滚同时检查实际已移走的副本。
- 安装/卸载各覆盖清理部分删除后失败：先结束回滚阶段，再清理，不破坏已提交结果；
