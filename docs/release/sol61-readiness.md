## 新会话与行为验证

- Direct：CLI 0.159.2，显式选择 `gpt-6.1-sol/high`，小改动实际选择 Direct、零子代理，只改目标 JSON。退出码 0。
- 自定义角色发现：同一新 CLI 会话仍报告 v1.1.0 的旧角色映射。该测试未更新全局安装，不能记为候选角色加载通过；也不能据此断言安装器升级失败。
- Solo：CSV 汇总跨两个实现文件，实际选择复用 Sol Host、零子代理。首轮在 240 秒限时结束，保留失败；确认进程组已停止后，新上下文接收当前候选和失败证据，修复空输入，最终 16 项测试通过。不是“一次顺利完成”的结果。
- 协作 CLI：Host 报告两个 Sol 独立实现并行，实际产物通过相关检查；但 JSON 事件导出未包含原始委派调用，因此不作为独立可重放的子代理模型/并行证据。配置额度为 2，已完成代理仍占名额，Luna 启动被拒，Astra 未启动。完整 6 项检查当时为 5 过、1 失败，整轮 BLOCKED；退出码 0 不等于任务通过。
- 分开补测：原 CLI 已结束后，桌面 Host 明确选择全新 `gpt-6-luna/max`，完成八条数据的机械批量；再选择全新 `gpt-6-astra/high`，只读检查类型校验和 Unicode 边界。最终夹具 6 项检查、Astra 补充 39 个输入情形均通过；Host 精确比较批量前后数据并重放保存的检查源码。**不能把这些补测合称为原 CLI 四角色流程一次通过。**
- 活跃旧写入者：真实测试进程每 0.2 秒改写文件。代理看到 tick 在一秒内增长，同时 `ps` 和 PID 探测受沙箱拒绝，保持写入范围、没有启动替代者，返回 BLOCKED。Host 事后核对确切 PID/命令，仅停止该测试进程，并收到退出码 0；该 PID 随后不存在。证明此次权限不足时安全停止，不证明所有交接场景。

原始运行输出哈希、输入、快照、失败和限时保存在[探针记录](../../tests/artifacts/sol61-release-probes.json)，
独立复核代码在[可重放检查](../../tests/artifacts/sol61-release-review-probe.py)。
桌面补测只承诺操作上的写入范围；其实际工具权限比角色配置更宽，不宣称 OS 强制隔离。

开发探针不覆盖所有真实项目，不证明自然路由在所有任务上正确，也不证明性能收益。
超时、失败和再次尝试需要保留；相同文件的快照只能证明净改动，不能证明没有临时写入。
