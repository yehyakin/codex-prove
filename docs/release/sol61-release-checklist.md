## 发布前操作与验收

先保留现有改动，再从审核通过的完整源码提交检出并检查；不可变文件快照用于比对，不替代安装所需的 Git 工作区。不要在脏工作区直接切分支、覆盖文件或安装运行包片段。本次准备没有执行全局安装、push、合并、打 tag 或发布。

### 只读预检

macOS / Linux，在完整候选源码目录运行：

```sh
bash scripts/test.sh
bash scripts/validate.sh
bash scripts/install.sh --check
git diff --check
```

Windows PowerShell 5.1，在完整候选源码目录运行：

```powershell
python -m unittest discover -s tests -q
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/validate.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -Check
```

使用 Python 3.11+；PowerShell 7 可改用 `pwsh -NoProfile -File`。`--check` / `-Check` 不写安装目标，不证明账号可调用模型或安装已生效。本机缺少 PowerShell，Windows 原生执行必须在最终 SHA 的对应 CI/环境中完成。

### 授权后的安装与验收

1. 保存拟安装的完整源码 SHA/manifest，确认只包含审核过的改动、许可证和本地资源；不带私有项目、rollout、凭据、依赖目录或实验工作区。
2. 按 [README](../../README.md#安装) 的安装器执行已选定候选，保存成功输出及备份位置。先前的 `main` 克隆命令不会自动选择此未发布候选。不要手工覆盖安装目录来绕过校验。
3. 新开 Codex 会话，检查 Skill/实际角色映射及模型可用性。对本次最终运行包的验收可复用完全相同哈希的实测证据，但必须标清其环境与失败/恢复。
4. 检查授权文件差异和独立需求验收；保留失败、重试、实际模型/权限和费用未知项。安装器成功、CLI 退出 0、代理说完成，均不能单独代替任务验收。

### 回滚

出现问题先停止继续升级，保留日志与安装器记录的备份。在相应源码目录使用：

```sh
bash scripts/uninstall.sh --restore-latest
```

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/uninstall.ps1 -RestoreLatest
```

这是恢复**最近一次受管理安装保存的旧字节**，不是任意历史版本选择或整份用户目录回滚；普通卸载不等于回滚。安装后被用户修改的受管理文件会触发拒绝，先检查并保留改动，不能强制覆盖。没有有效备份时不要声称可以恢复旧版。安装器不改原有 `~/.codex/config.toml`，无关角色和配置仍需保留；恢复后重新开会话并验证。
