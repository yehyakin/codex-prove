## 用途与结论

README 候选配图，暂不替换现有四张 SVG，不改 README 文案、不提交、不合并、不发布。
两种主题各有中英文版本；导出 1200×676 静态封面、无声 MP4、循环 GIF 和本机条件允许的 Live Photo 资源包。高度取偶数以兼容 H.264/yuv420p。

1. **模型分工**：Sol 6.1 执行完整任务，Astra 做按需只读分析，Luna 做规则明确的机械批量。
2. **完整任务**：默认由一个 Sol 在同一上下文规划、实现、验证；只有独立工作才值得分工。

四个稳定角色 ID 对应三种模型；不是固定要求四个角色都启动。Direct 仍由当前 Codex 直接完成。
示意路径、卡片数量、运动速度没有数量或性能含义，不展示或暗示实测成本、吞吐或速度收益。

## 视觉与素材

沿用项目深蓝、橙色、薄荷色、淡紫色；增加原创任务卡、代码文件、检查标记，表示对象与流程。
不用外部照片、厂商标志、emoji 或生成的品牌图；图形均为原创 SVG/HTML 示意，非应用实际截图。
顶部保留 Codex PROVE 与候选状态。主体大字稳定，说明短句；角色卡片用位置和线条解释关系。
最小信息在静态封面中完整可见；候选标记、只读与按需限定不依赖动画才能读到。

## 分镜

所有版本 30 fps、150 帧（5 秒）；封面取第 126 帧，即 4.2 秒。

| 时间 | 模型分工 | 完整任务 |
| --- | --- | --- |
| 0.00–0.40 s | 完整标题已可读，Sol 主卡与任务单稳定出现 | 标题已可读，一份任务单进入同一上下文容器 |
| 0.40–1.40 s | 文件卡进入 Sol，说明完整任务由它负责 | 任务卡依次经过规划、实现、验证节点 |
| 1.40–2.70 s | 可选路径逐步显现，Astra 分析卡与 Luna 批量卡出现 | 代码文件和检查标记按阶段出现，不换上下文 |
| 2.70–3.50 s | 结果沿返回路径回到 Sol；限定“按需”持续可见 | 汇总为结果卡；辅助说明保留 Direct 与按需分工边界 |
| 3.50–5.00 s | 停留在完整封面；126 帧取静态图 | 停留在完整封面；126 帧取静态图 |

GIF 循环仅作网页预览，不代表原生 Live Photo。网页另有静态/减少动效方式。
本地 Live Photo 封装不导入照片图库，也不请求图库权限；手机、锁屏和社交平台兼容性不在本次验收内。
